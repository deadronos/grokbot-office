# ADR 0001: Hono on Node.js for the API

Status: Accepted

## Context

The office needs a small JSON API (health, bots, events, viewer state and stream), a
static web app served from the same process in production, request body limits, exact
CORS origins with credentials, and a testable app module that can be built with an
in-memory repository. The whole server must run as one Node.js 24 process on a Mac
behind a loopback-only listener; there is no separate edge runtime or container
platform to accommodate.

## Decision

Use [Hono](https://hono.dev) on `@hono/node-server`.

- `createApp({ repo, ... })` returns the whole app, so tests call `app.request()`
  with a fake repo and no network. The boot entry (`apps/server/src/index.ts`) owns
  the database, listeners and shutdown.
- Middleware is plain composition: security headers, the CORS allowlist, surface
  allowlisting, rate limiting, auth and CSRF are small `app.use` layers with explicit
  order, not plugins with hidden lifecycle hooks.
- Hono's cookie, body-limit and static-file helpers cover the viewer cookie,
  the 16 KB API body cap and `serveStatic` for the built web app without extra
  dependencies.
- A `surface: "bot" | "viewer" | "all"` option builds the same app for the
  two-listener production layout, so the public Funnel port can be a hard route
  allowlist rather than a second code path.

## Consequences

- Middleware order is load-bearing (for example, the CORS layer sets headers after
  the response exists, because Hono's `cors` helper would clobber a stream's headers),
  and the surface check must run after health and bot routes are known.
- `@hono/node-server` gives us Node's `IncomingMessage` on `c.env.incoming`, which is
  how the rate limiter reads the socket address instead of trusting
  `X-Forwarded-For`.
- The server is coupled to Node.js, which is where SQLite (better-sqlite3) already
  runs. That is acceptable for a single-Mac deployment.
- A framework with more built-in structure (Fastify, Nest) would add schema/plugin
  machinery the API does not need; Express would need more manual typing for
  context variables.

See [ADR 0002](0002-drizzle-sqlite.md) for the database and
[ADR 0003](0003-sse.md) for the live stream.
